# Reproduce Legal-AI locally

1. Read the [README](README.md) and pick the smallest corpus that covers the request. Start with the Tantivy quick start for an Indian legislation demo or the synthetic JSONL example in [architecture](docs/architecture.md) for an offline index smoke test.
2. Reuse `.venv` if it uses Python 3.14 and its dependencies match `requirements.txt`. Otherwise create a compatible environment using the quick start. Reuse verified shards and indexes already present. Run the documented status command and verify a keyword result with its source locator. For citations, verify an exact lookup as well.
3. Use [Qdrant](docs/qdrant.md) when semantic search is requested and a compatible snapshot covers the topic. Start with the Acts pilot. Verify the exact count of an existing restore before reusing it. For a fresh restore, run the disk-space check against the existing parent of the selected storage directory. Use a dedicated container with an unused name, port, and storage directory. Record the exact count and query result. Choose large downloads only when the requested scope calls for them.
4. Consult [source and API links](docs/tools-and-sources.md) for gaps and [the validation checklist](docs/workflow.md) for research. Record source versions, coverage, citation pinpoints, and any unavailable checks. Keep generated files and matter data under ignored local directories.
5. Report the environment, installed route, files indexed, verification commands, and any steps still pending. Separate a tested quick start from optional integrations and from legal conclusions.
